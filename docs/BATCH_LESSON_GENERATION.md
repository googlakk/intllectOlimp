# Массовая фоновая подготовка уроков

## Как пользоваться

В «Уроках» выберите класс и предмет. Отметьте нужные темы в КТП,
нажмите «Создать выбранные», выберите общую модель и язык и запустите
подготовку. Также можно выбрать раздел целиком или только темы без материалов.
За один запуск доступны до 30 тем одного предмета.

После принятого запуска страницу можно закрыть: задачи выполняет сервер.
При возвращении список восстанавливается из базы без сохранённого в браузере
идентификатора. Видны все активные группы и три последние завершённые.
Для каждого урока отображается очередь, подготовка, готовый результат,
ошибка или отмена. Готовые материалы сохраняются черновиками;
перед публикацией учитель проверяет их в редакторе.

Уроки с опубликованной версией, архивные темы и темы без целей обучения
исключаются из выбора. Для заполненного черновика необходимо подтвердить
замену материалов. Новые правки или публикация, появившиеся после запуска,
не перезаписываются результатом генерации.

«Остановить очередь» отменяет ожидающие задачи. Уже начатые завершаются.
Ошибка одного урока не останавливает остальные. «Выбрать уроки с ошибками»
выбирает доступные темы для нового, явно подтверждённого запуска.

## Работа сервера

- POST `/api/lessons/generate/batch`: предмет, 1–30 уникальных тем,
  teacher_id, UUID request_id, optional model/content_language,
  replace_existing_drafts. Проверяются все темы до начала внешних вызовов.
- Все задания сохраняются одной транзакцией в существующие метаданные уроков
  до запуска фоновых задач. Новых таблиц и миграций нет.
- Один общий лимит — два урока одновременно — используется массовыми,
  одиночными фоновыми и прежними синхронными запросами генерации.
- GET `/api/lessons/generate/batches?subject_id=…` восстанавливает список;
  GET `/api/lessons/generate/batches/{UUID}?subject_id=…` возвращает группу.
- POST `/api/lessons/generate/batches/{UUID}/cancel?subject_id=…`
  отменяет только ожидающие задачи под блокировкой записи.
- Повтор того же UUID и параметров возвращает прежнюю группу. Изменённый
  набор параметров с тем же UUID отклоняется. Ошибки сети не запускают
  автоматические повторные POST. Потерянный ответ восстанавливается опросом.
- Доступ учителя ограничен назначенными предметами; администратор работает
  внутри своей организации. Статусы проверяют тот же доступ.

Лимит параллельности действует на один процесс; текущий запуск production
использует один worker. Для нескольких worker/replica понадобится общая очередь.
После перезапуска сервера незавершённые задачи получают ошибку и требуют
ручного повторного запуска. Автоматического повторения платной генерации нет.
На выполнение начатого задания отведено 15 минут; ожидание ограничено временем
для 30 последовательных заданий. Готовые результаты других уроков сохраняются.

Компактная история остаётся в метаданных для проверки старых request_id;
она растёт линейно с числом запусков. Ответ опроса ограничен активными группами
и тремя последними завершёнными; группировка выполняется за один проход.
Служебные маркеры исключены из содержимого уроков для клиентов и новых снимков
версий. Удаление всей неиспользуемой программы удаляет её историю.

  10 subtests, 3 skipped; 353 frontend tests; архитектура, TypeScript,
  production build (9,94 с).
- После финального теста независимости от запроса и уточнения текста ошибки
  полный backend-набор прошёл повторно: 764 pytest, 10 subtests, 3 skipped.
  Фронтенд с момента полного quality gate не менялся.
- Проверены атомарное резервирование, доступ ко всей группе, идемпотентность,
  общий лимит двух задач, точное однократное получение задания, отмена и её
  гонка с началом работы, истечение времени, перезапуск сервера, защита версий
  и сохранение истории после дальнейшей генерации.
- Фоновая независимость проверена настоящим диспетчером задач с подменённым
  генератором: запрос уже завершён, два урока работают, третий ждёт; после
  освобождения мест третий запускается без GET статусов и участия браузера.
- Браузер с полностью подменённым API: три выбранных темы с общей моделью
  и кыргызским языком; восстановление после обновления; готовый, ошибочный и
  отменённый урок в одной группе; выбор только ошибки; подтверждение замены;
  потерянный принятый ответ без дублирующего запуска; ширина 320 px без
  горизонтальной прокрутки.
- Снимки интерфейса: `output/playwright/batch-generation-desktop.png`
  и `output/playwright/batch-generation-mobile.png`.
- Горячая замена файлов во время dev-проверки вызвала устаревший экземпляр
  AuthContext; полная перезагрузка устранила ошибку. В окончательной сборке
