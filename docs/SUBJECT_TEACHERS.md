# Предметные учителя

Опубликовано на `https://inet.edu.kg` с кодом `ad08d67`, Railway deployment `9d6b8f8a-c5af-4808-9806-0708b3bcda22` (SUCCESS). Владелец подтвердил применение миграции; startup и health endpoint проверены. Создание реального аккаунта и платная генерация после выкладки не запускались.

Реализовано локально 29 сентября 2026. Администратор создаёт учителя, выбирает существующие предметы по классам программы (например, математика 7 и 8). Учитель самостоятельно запускает генерацию, проверяет, редактирует и публикует уроки в уже загруженных темах.

3. В `/admin/accounts` → «Предметные учителя» создаёт учителя или открывает «Предметы и классы» у существующего.
4. Выбирает предметы и параллели. Новый учитель получает логин и временный пароль через существующий механизм аккаунтов.

**Существующим учителям нужно явно назначить предметы.** Назначение к 8А больше не даёт доступ ко всем предметам 1–8 классов. Без предметных назначений список тем пуст. Миграция не угадывает предмет по старым классам или имени учителя.

## Два разных назначения

- Предмет + класс программы (`Subject.id`, уже содержащий grade): доступ к темам, урокам и связанным учебникам. Можно назначить несколько предметов и классов.
- Учебный класс со списком учеников (`ClassroomTeacher`, например 7А): существующий доступ к ученикам и их общим отчётам. Это назначение не открывает материалы других предметов.

Для создания предметного учителя учебный класс со списком учеников не обязателен. Создание/изменение КТП, названий предметов, разделов, тем, архивирование и перестроение учебного графа доступны администратору. Учитель работает с содержанием уроков существующих тем.

Если нескольким учителям назначен один предмет одного класса, они работают с общей программой и общими уроками: личные копии курса и распределение конкретных тем в этой версии не вводились. Отдельный процесс утверждения урока другим проверяющим также не добавлялся.

## Реализация

- `backend/teacher_assignments.py`: отдельный DeclarativeBase, исключён из startup create_all.
- `backend/services/teacher_assignments.py`: назначения, проверка готовности схемы, валидация, изменение с блокировкой профиля, журнал действий.
- `backend/services/accounts.py`, `backend/routes/accounts.py`: создание вместе с назначениями одной транзакцией; PUT `/api/accounts/teachers/{profile_id}/subjects`; GET `/api/accounts/teacher-subjects/options`.
- `educator_access.py`, `catalog.py`, `dashboard.py`, `textbooks.py`, `textbook_links.py`: точный предметный доступ, включая прямые обращения по ID. Проверки уроков, генерации, публикации и медиа используют общую цепочку доступа.
- `src/features/accounts/SubjectTeachersPanel.tsx`: создание и изменение назначений независимо от наличия учебных классов.
- `src/pages/teacher/Lessons.tsx`, `features/teacherLessons/listViews.tsx`: назначенная программа и действия учителя.

Таблица закрыта от браузерного Data API (RLS, отозваны anon/authenticated/PUBLIC grants). Управление проходит через FastAPI с проверкой администратора и организации. Использован принцип явных прав из [документации Supabase](https://supabase.com/docs/guides/database/postgres/row-level-security).

До обновления сервера/схемы форма не позволяет отправить создание без поддерживаемых назначений. Отсутствующая схема даёт понятную ошибку 503. Снятие всех предметов сохраняет аккаунт, но закрывает доступ к учебным материалам; уже открытый экран может показывать ранее загруженную информацию, следующие обращения проверяются сервером заново.
