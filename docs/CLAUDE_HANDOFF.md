## 1. Владелец и жёсткие правила

Владелец пишет по-русски и ждёт ответов по-русски: коротко, по делу, без канцелярита. Он не программист — объясняй,
что изменится для учителя и ученика, а не только в коде.

Правила (нарушать нельзя):

- **Выкладка на прод — только после слова «выкладывай» / «выложи»** (или прямого «да» на вопрос «выкладывать?»).
  Коммит и push в GitHub выкладкой не являются (см. раздел 2).
- **Платная генерация** (HeyGen-видео, распознавание учебника моделью, массовая генерация уроков, картинки) —
  только с согласия владельца. Одиночную пробу предлагай сначала.
- **Миграции применяет владелец.** Ты кладёшь готовый SQL в `supabase/migrations/<timestamp>_<name>.sql`
  и говоришь, что применить. Сам миграции не запускаешь. Новые таблицы — в отдельном наборе моделей
  (как `TutorBase`, `TextbookBase`, `FeedbackBase`), чтобы `create_all` при старте их не создал.
- **Чтение продовой базы тебе заблокировано** (владелец так настроил). Локальный бэкенд и прод смотрят
  в **одну и ту же** базу Supabase — поэтому скрипты против «локальной» базы = против прода. Для диагностики
  используй логи Railway (`railway logs --service web`), тесты с подменой БД и код.
- **Никогда не печатай** `.env`, ключи, токены, строки подключения. Имена переменных выводить можно,
  значения — нет (читай их в скрипте и передавай через stdin, как в разделе 2).
- Не трогай авторизацию, права, версии публикаций, попытки учеников и реальные данные курсов без прямой задачи.
- Не делай `git reset --hard`, `git clean`, массовых удалений; неотслеживаемые файлы удаляй только с согласия.
- **Бэкенд без `--reload`**: после изменений бэкенда говори владельцу перезапустить локальный сервер.
- Процесс для нетривиальных задач: Discover → Plan → Implement → Review → Verify → Report, **коммит на каждый шаг**.
  Гейты: `pytest` (из `backend/`), `pnpm run check:architecture`, `pnpm run check:quality`.
  Архитектурная проверка ругается на слово `any` даже в строках/названиях тестов — не пиши его.
- Ревьюер-субагент полезен, но у владельца бывает исчерпан лимит расходов — тогда субагенты падают
  с 429; делай работу сам и честно пиши, что независимого ревью не было.

Предпочтения владельца: действовать самостоятельно в согласованной задаче, не переспрашивать очевидное,
не скрывать непроверенное. Урок = «учебник + учитель», кратчайший путь к целям урока; вид урока не
переделывать целиком — улучшать точечно.

## 2. Где что работает и как выкладывать

| Что | Где |

| Сборка | `Dockerfile`: фронтенд собирается pnpm, бэкенд — uvicorn, раздаёт и API, и собранный SPA |

**Railway НЕ подключён к GitHub.** Push в `main` прод не обновляет. Выкладка — из этой папки:

```bash
git checkout main && git merge --ff-only dev/lesson-experience && git push origin main && git checkout dev/lesson-experience
railway up --ci --service web          # загрузка рабочей копии (фильтр .railwayignore) и сборка, ~2–3 мин
railway deployment list                # последняя должна быть SUCCESS
railway logs --service web --lines 200 # «Application startup complete», без Traceback
```

`.railwayignore` исключает `.env`, `node_modules`, `.venv`, сборки и диагностику. Railway CLI залогинен
под аккаунтом владельца и привязан к проекту. Проверка, что прод отдаёт новый код: скачать главный
`/assets/index-*.js` и поискать строку из нового кода.

**Переменные окружения Railway** (имена; значения — в Railway): `DATABASE_URL`, `SUPABASE_URL`,
`SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `ANTHROPIC_API_KEY`, `ANTHROPIC_WORKSPACE_ID`,
`OPENROUTER_API_KEY`, `LLM_PROVIDER_KTP_COLUMNS`, `LLM_MODEL_KTP_COLUMNS`, `HEYGEN_API_KEY`, `HEYGEN_BASE_URL`,
`HEYGEN_TIMEOUT`, `TUTOR_ENABLED=true`, `TUTOR_BURST_PER_MIN`, `TUTOR_MAX_MESSAGE_CHARS`,
`TUTOR_DISABLE_THINKING`, `TEXTBOOK_AI_ENABLED`. `HEYGEN_WEBHOOK_SECRET` пуст и локально, и на проде
(вебхук HeyGen не используется — см. раздел 4.7). Новая переменная в коде = добавить её в Railway:

```bash
# значение из локального .env через stdin — не попадает в вывод
railway variable set NAME --stdin --skip-deploys --service web
```

**Локальный запуск:** `./start-local.sh` — бэкенд `http://127.0.0.1:5000`, фронтенд `http://localhost:5173`
(Vite). Проверка бэкенда — `GET /api/healthz`. Перед запуском посмотри, не занят ли порт (`lsof -nP -iTCP:5000`),
и не убивай чужие процессы. Старт бэкенда меняет схему базы (совместимость, см. 4.10) — а база общая с продом.

## 3. Архитектура и карта файлов

## 4. Что сделано (по областям)

### 4.1 Учебный цикл и доступ
- Типы уроков study/review/assessment/reflection/project, черновик и опубликованная версия, попытка закреплена
  за версией, история попыток (`docs/LEARNING_CYCLE.md`).
- **Ученик видит только предметы своего класса** (`Subject.grade == student.grade`; класс ученика берётся из класса,
  в который его добавили). **Темы открываются строго по порядку** (`services/curriculum_graph.py`,
  `refresh_student_access`, advisory lock). Если тема после пройденной остаётся закрытой и после пересчёта,
  пересчёт для тех же строк не повторяется (`_confirmed_locks`).
- **Отложено:** в обычных уроках сервер доверяет «верно/неверно» из браузера (перепроверяются только контрольные,
  `services/assessment.py`). План: браузер шлёт `responses`, сервер проверяет тем же `check_answer`.

### 4.2 Генератор и профили предметов
- Профиль предмета поверх семейства (`ai/subject_profiles.py`): маршрут урока, ход мысли, правила, заблуждения,
  план блоков, проверки качества после генерации.
  - **История**: лента времени, источник, причины и следствия; фирменные блоки `ChronologyLine` (vis-timeline)
    и `CauseEffectMap` (React Flow).
  - **Математика/алгебра** (не геометрия): пример как в учебнике → решение по шагам → «найди ошибку» →
    самостоятельная задача → проверка подстановкой; фирменные блоки `StepSolver` и `FunctionExplorer`;
    задачи должны ссылаться на учебник (`source_ref`), иначе предупреждение.
  - Геометрия, физика, химия, биология, языки — пока без профиля (семейства по умолчанию). Следующий кандидат —
    геометрия (чертёж → доказательство по шагам).
- Урок по учебнику: подтверждённый параграф идёт в генератор кэшируемым блоком; проверка «по книге»
  в отчёте качества (`ai/textbook_grounding.py`).
- Генератор знает 29 блоков (`ai/generator.py`, «Допустимы только следующие 29 компонентов»); число
  проверяется тестом — при добавлении блока обнови текст и `test_generator.py`.

### 4.3 Фирменные блоки математики
- **StepSolver «Решаю по шагам»**: ученик пишет решение строками; выражение — равно заданию по смыслу; уравнение —
  равносильно (пропорциональность разностей частей или те же корни: знаменатель и квадрат без посторонних корней
  засчитываются, деление на x — нет); «найдены не все корни», тождество/«нет корней», названные типичные ошибки,
  подсказка к шагу, образец после двух ошибок. Движок — `features/interactiveEngines/stepSolver.ts`, копия
  на Python — `services/math_expression.py` (проверка данных модели, оценка строки для тьютора).
- **FunctionExplorer «График по формуле»**: SVG-плоскость, ползунки параметров, прогноз до графика,
  график-цель пунктиром, «Показать ответ» после 12 движений.
- StepSolver проверяет только «выражение, равное заданию» и «равносильное уравнение». Задания про ОДЗ, нули дроби,
  «при каких значениях», неравенства и ответы вида «y ≠ 5» он пройти не даёт — генератору это запрещено
  (`ai/generator.py`, п. 27), а `step_solver_problem` в `services/math_expression.py` делает из такого блока ошибку
  публикации. Над полем ввода — подсказка формата; строку можно начинать с «=» (`= 5x`).
- **Браузер и сервер обязаны считать одинаково**: общие наборы случаев `backend/fixtures/answer_check_cases.json`
  и `backend/fixtures/step_solver_cases.json` прогоняют и pytest, и vitest. Меняешь разбор — меняй оба и добавляй случай.

### 4.4 Сверка ответов
- Режимы (`answer_mode`): `form` (по умолчанию для выражений — важна запись: «раскройте скобки», «сократите
  дробь»), `equivalent` (уравнения, вычисления, числовые), `choice` (варианты — только точно).
- Разбор выражений понимает: `2√3`, `sqrt()`, LaTeX `\frac/\dfrac/\tfrac/\sqrt` **с вложенными скобками**,
  смешанные числа `2 1/2` и `2\frac{1}{2}`, модуль `|x|` (один уровень), `½`, `\div`, `:`, кириллическую «х»
  вместо x. Текст задания («Упростите: …», `$…$`) извлекается только из полей задания, **не из ответов**.
- Поле ответа `components/blocks/MathAnswerInput.tsx`: кнопки дроби/корня/степени и запись «как в тетради».
- `lessonContent.ts`: литеральное `\n` превращается в перевод строки, **кроме** команд LaTeX (`\neq`, `\ne`,
  `\nabla`, `\not`, `\nu`…) — раньше «x ≠ 0» ломалось в «xeq0».

### 4.5 Публикация

### 4.7 ИИ-аватар (HeyGen) — цепочка
1. Учитель в редакторе («Дополнительные настройки → аватар») выбирает профиль и голос, жмёт «Создать N реплик».
2. `POST /api/avatar/jobs` на каждую реплику (`cue`). Медиа пишется **в черновик**: у опубликованного урока первая
   реплика создаёт черновик с новым номером версии, редактор шлёт остальные в версию из ответа, а сервер
   устаревший номер переводит в актуальный черновик (`services/avatar._avatar_draft_version`).
3. Готовность: **фоновый опрос** `services/avatar_poller.py` (каждые 30 с, задания до 7 дней, строка задания
   под `FOR UPDATE`) + опрос из открытого редактора (8 с). Вебхук HeyGen есть в коде, но адрес при создании
   видео не передаётся — полагаемся на опрос.
4. Готовое видео копируется в **закрытую корзину Supabase `avatar-videos`** (есть, `public = false`),
   `LessonAsset` с `storage:avatar-videos/...`. Если текст реплики в опубликованной версии дословно тот же —
   видео прикрепляется и к ней (ученик видит сразу); иначе остаётся в черновике — нужно «Обновить публикацию».
5. Ученик: `GET /api/avatar/cue-assets?lesson_version_id=…` — подписанные ссылки на все реплики урока одним
   запросом; сопоставление по `cue_id` (`cue-{номер блока}` или `cue-{номер}-{slide_id}`); `<video>` играет
   напрямую из хранилища. Нет видео — голос браузера.
6. Движок HeyGen v3 `avatar_iii`, кадр `aspect_ratio: auto` + `fit: contain` (голова не обрезается);
   фото-аватар учителя — через v3, аватары каталога — через v2.
- Задания, которые не могут завершиться (урока/версии нет, тема в архиве, документ урока не проходит проверку —
  404/409/422), опрос закрывает как failed с причиной. 2026-09-27 так закрыты старые задания 15–27
  (422 «урок должен содержать хотя бы один эпизод»).

## 7. Известные проблемы и следующие шаги

1. **Геометрия** — свой профиль (чертёж, доказательство через ProcessBuilder) после проверки алгебры на реальных уроках.
2. **Распознать учебник «Алгебра 8»** (сначала проба 5–10 страниц, ~$0.1–0.3) — только с согласия.
3. **Серверная перепроверка ответов** в обычных уроках (см. 4.1).
4. **Сессии**: в логах видно `POST /api/auth/refresh 400` и выход, когда в одном браузере учитель и ученик —
   одноразовый refresh-токен Supabase расходуется другой вкладкой. Не исследовано.
5. **Старые уроки** с документом без эпизодов (422) — аватар к ним не прикрепить; нужна перегенерация.
6. `HEYGEN_WEBHOOK_SECRET` пуст — если понадобится мгновенное завершение, передавать `callback_url` в HeyGen и задать секрет.
7. Локальный бэкенд владелец перезапускает сам; после изменений бэкенда напоминай.
8. **Старые уроки алгебры со StepSolver про ОДЗ/нули дроби** (владелец наткнулся на «Найди допустимые значения и нули
   дроби», y/(y²−5y); какая тема — не выяснено) пройти нельзя. Опубликованные уроки при открытии не перепроверяются —
   нужна ручная замена блока или перегенерация; новая проверка остановит их при «Обновить публикацию».
9. Не проверено вживую, что генератор после правила п. 27 выбирает другой блок (нужна платная генерация).
10. Незакрытые риски учебного цикла из прошлой передачи (сохранение ответов контрольной при уходе со страницы,
   очередь сохранения прогресса при ошибке, отображение прежних попыток после новой публикации) — проверить тестом
   перед тем как объявлять надёжными.
