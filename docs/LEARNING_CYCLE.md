# Учебный цикл и публикация уроков

## Поведение

Учитель создаёт предмет и раздел без импорта КТП, добавляет занятие, проверяет цели и охват,
готовит ИИ-черновик или вручную добавляет материалы, смотрит предпросмотр и публикует.
Типы занятий: изучение (`study`), повторение (`review`), контрольная (`assessment`), разбор ошибок (`reflection`), проект (`project`).
Контрольная и повторение используют навыки охватываемых тем. Разбор может ссылаться на контрольную.

Черновик хранится отдельно от опубликованной версии. Изменение содержания, параметров темы,
аватара и медиа не заменяет опубликованную версию до явной публикации. Начатая попытка
остаётся на исходной версии. Убрать из программы означает архивировать; восстановление
возвращает занятие в черновик. Старые результаты доступны в истории.

Контрольная — самопроверка без таймера. Ответы вводятся без немедленной обратной связи,
сервер проверяет их при сдаче. Новая попытка не удаляет завершённую. Обновляется только
освоение навыков с конкретными проверочными свидетельствами. Повторное сохранение
завершённой попытки не создаёт дополнительных свидетельств.

## Обновление существующей базы

1. Создать резервную копию и проверить миграцию на копии базы.
2. Применить `supabase/migrations/20260924122116_learning_cycle.sql` принятым способом
   развёртывания миграций **до запуска обновлённого backend**.
3. В окружении с нужным `DATABASE_URL` выполнить из `backend` сначала
   `../.venv/bin/python repair_learning_curriculum.py` для просмотра предметов,
   затем `../.venv/bin/python repair_learning_curriculum.py --apply` для пересборки
   автоматически выведенных связей. Авторские связи и опубликованные материалы сохраняются.
4. Учитель проверяет отмеченные занятия: назначение, охват и цели. Старые материалы
   не перегенерируются автоматически; новая контрольная проходит проверку допустимых заданий.
5. После применения проверить создание, публикацию, сдачу и архивирование тестового занятия.

Миграция добавляет поля темы, указатель опубликованной версии, исходные ответы контрольной
и таблицу `lesson_attempts`. Завершённые старые результаты копируются в историю.
Новая таблица закрыта для прямых клиентских ролей; доступ идёт через защищённый backend.
Старые результаты без подробных свидетельств не подтверждают новые навыки.
Production-миграция и публикация в рамках реализации не выполнялись.

## Проверки

- Общий контроль качества: `pnpm run check:quality`.
- Интеграционные тесты: `backend/test_learning_cycle_integration.py`.
  Запускаются только при явном `LEARNING_CYCLE_TEST_DATABASE_URL` на localhost и базе
  с именем `learning_test`; отдельная тестовая БД обязательна. Проверяют миграцию,
  создание, версии, историю, повторную сдачу, архивирование и восстановление.
- Браузерные тестовые данные и скриншоты: `output/playwright/teacher-cycle-fixture.js`,
  `output/playwright/teacher-preview-mobile.png`, `output/playwright/student-reflection.png`.
  Браузерная проверка использует подменённые ответы API; реальное хранение отдельно проверено PostgreSQL-тестами.

Тесты генерации используют подменённого поставщика ИИ. Качество новых сгенерированных
материалов в любом случае проверяет учитель перед публикацией.
